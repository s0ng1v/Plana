# 工作流（前端先行）

状态：agreed（2026-11-17）
更新时间：2026-11-17

## 1. 一页的完整流程

1. **读共识**：constitution.md → product.md → design-system.md → 该页 features 规格。
2. **补规格**：规格里缺的交互，先补进 features 文档，再动手。
3. **搭壳**：页面结构 + 设计令牌接入，数据用假数据，不写业务特例。
4. **做交互**：按规格实现状态机，确保每个状态都能手动触发。
5. **自检**：对照清单逐条过，跑 100% / 125% / 150% DPI。
6. **截图存档**：放 `harness/assets/<页面>/`，命名 `<状态>@<DPI>.png`。
7. **请用户验收**：清单打勾 + 截图；未通过则记录差异并回到第 3 步。
8. **记录**：在 decisions.md 追加本次非规格内的决定。

## 2. 页面依赖

- 今日小组件先做，因为它同时验证：窗口宿主、亚克力、字体渲染、DPI、输入交互。
- 月历小组件复用 WidgetHost 与令牌，只新增日历网格与农历数据。
- 任务页沉淀 `TaskRow`、`CheckBox`、`TaskDetailPanel` 三个基础组件。
- 四象限复用 `TaskRow` 与分组逻辑。
- 日历页复用月历网格（从小组件抽成控件）。
- 设置页最后做，承接前面暴露的所有开关。

## 3. 假数据约定

- 10 条中文任务：覆盖高/中/低/无优先级、今天/明天/已完成。
- 2 个清单：收集箱 + 1 个自建清单（如「工作」）。
- 假数据集中在 `VGList.App` 的 `SampleData`，禁止散落在 View。
- 重启即重置，不做本地持久化。

## 4. 验收方式

- 清单逐条打勾，不允许"整体感觉像"。
- 小组件验收：像素级，逐项比对尺寸、字重、颜色、间距。
- 主窗口验收：结构级，比对布局、层级、信息密度、视觉一致性。
- 每页至少两张截图：深色、浅色。

## 5. 禁止事项

1. 未做规格的"顺手优化"。
2. 提前接 SQLite、提醒、同步。
3. 用十六进制色值写死在 XAML。
4. 用 `MessageBox` 或默认控件样式交差。
5. 页面没验收就开下一页。
6. 在同一提交里混合两个页面的改动。

## 6. 提交约定

- 每次提交只做一件事：一页、一个组件或一处规格修正。
- 提交信息格式：`<范围>: <动作>`，例如 `widget/today: 实现优先级快捷条`。
- 涉及共识变更的提交，必须同时包含 harness 文档改动。
